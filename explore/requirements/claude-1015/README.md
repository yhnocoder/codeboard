# claude-1015：需求探索

2026-10-15 这一轮的探索产物。用 nano-vllm 做例子，把 CodeBoard 的「感觉」做成能上手的原型。

| 目录 | 是什么 |
| --- | --- |
| `01-flow-options/index.html` | 第一版讨论稿：同一段 `generate()` 流程的四种画法（A 逐层展开、B 泳道、C 嵌套、D 数据流）。浏览器直接打开。 |
| `prototype/` | 可交互原型，Vite + SolidJS。能拖动、能创建，刷新就重置。 |
| `prototype/preview.html` | 原型打包成的单个文件，双击就能在浏览器里打开。 |

## 运行原型

```bash
cd prototype
npm install
npm run dev            # 开发模式
npm run build:single   # 重新打包 preview.html（产物在 dist-single/）
```

nano-vllm 作为 submodule 放在仓库根目录的 `examples/nano-vllm`（钉在 `bb823b3`），所有测试和原型都用这一份。克隆后先运行 `git submodule update --init`。原型用的源码快照 `prototype/src/data/nanovllm.json` 由 `npm run extract` 从这个 submodule 生成，包含 HEAD `bb823b3` 和旧版本 `9e8507e` 两个 commit。

## 原型里可以试的

- **拖动**：拖卡片的标题栏或便签正文；拖分组框的标签会带着框里的卡片一起走；拖空白处平移，`⌘/Ctrl + 滚轮` 缩放。
- **展开调用**：代码里能解析到定义的调用，鼠标悬停时会出现下划线。点一下就会在旁边生成被调函数的卡片，并从这一行连一条箭头过去，编号自动接上（如 3.2.2）。同名定义有多个时会弹出菜单让你选。
- **连线**：鼠标移到某一行，右侧出现小圆点，拖到另一张卡片上就是一条「调用」箭头；拖到空白处会顺手建一张便签。点箭头可以改标签和类型。
- **创建**：双击画布或按 `N` 建便签；底部工具条可以加分组、图片（也能直接拖文件进来）和网页（也能直接粘贴网址）；左侧「文件」打开源码，拖选几行后点「生成卡片」，或者点函数旁边的「＋ 卡片」。
- **新版本提示**：主流程里的 `Scheduler.schedule` 和 `postprocess` 钉在旧 commit 上，右上角是黄点。点开能看到真实的 diff，选「跟进」之后，高亮行和从这张卡出发的箭头会按内容迁移到新行号。
- **讲解**：按 `P` 或点顶栏「讲解」，方向键按编号一步步走，其他卡片变暗。
- **追踪（示例）**：顶栏开关会叠加一份示例运行数据，演示阶段二的追踪结果填在哪里。
- **搜索**：`⌘K` 或 `/` 搜函数、类、文件、卡片，回车把函数放到白板上。
- **布局**：顶栏切换「工作台」和「专注」，快捷键 `\`。

## 我拍板的决策

1. **流程用「逐层展开」画。** 横向是同一层按顺序发生的事，往下是展开其中某一步。下级卡片缩进放在上级下方，箭头从左边进入，像一棵展开的树。四种画法里，这种最接近读代码时脑子里的样子，也能直接容纳追踪数据。
2. **箭头从代码的具体一行出发。** 这是和普通白板最大的区别：箭头说明了「是这一行调用了它」。所以代码卡片的行高是固定的（20px），箭头才能对准行。
3. **点调用就展开，是构建流程的主要方式。** 手动摆卡片太慢。点一下，就能完成建卡、连线、编号、摆位置这四件事。画布上已经有的函数不会重复建卡，只补一条箭头。
4. **编号就是讲解顺序。** 编号是层级式的（3、3.1、3.2.1），按出发行号自动排。讲解模式和左侧大纲都基于编号和箭头，不需要单独维护。
5. **另外三种画法不单独做视图，而是并进主画布。** 数据流（D）变成箭头标签，嵌套（C）变成左侧大纲（按箭头自动生成），泳道（B）等读多进程代码（DeepEP、vLLM worker）时再加。
6. **卡片钉在 commit 上，源码变了只提示。** 黄点表示有新版本，点开看 diff，由你决定跟进还是留在旧版本。按符号（如 `Scheduler.schedule`）同步；没有符号的片段卡片按内容找。
7. **追踪数据的三个落点现在就定好。** 箭头标签填值的摘要（`logits [2, 151936] bf16`），卡片角标填调用次数（`×256`），循环箭头填轮数。阶段二只需要往这三个位置填数据。
8. **两种布局都保留。** 「工作台」是三栏：白板和大纲、画布、源码，适合边读边搭。「专注」只留画布，源码浮在右侧，适合讲解和复习。两种布局只是界面外壳不同，底下是同一套白板数据。
9. **视觉方向。** 暖灰色画布、白色卡片，便签用纸色。陶土色只用在需要你看一眼的地方：编号、选中、数据流箭头。标题用衬线体，代码用 JetBrains Mono。浅色和深色模式都做了。
10. **白板数据不写进被读的仓库。** 白板存在 CodeBoard 自己的工作区目录里，锚点记录「仓库 + 路径 + 符号 + commit」。

## 原型刻意没做的

保存、撤销、多选、编辑源码、真正的 tree-sitter 解析（现在用的是一个够用的 Python 词法高亮和缩进规则）、多仓库工作区、Triton/CUDA 高亮。这些不影响判断「感觉对不对」，所以留到后面。

流程怎么展示：四种画法

同一段逻辑画四遍：nano-vllm 里 LLM.generate() 一次推理循环，代码取自 commit bb823b3，行号都是真实的。卡片和箭头是静态示意，方案 C 的折叠可以点。看完告诉我你喜欢哪种，或者哪几种的哪部分。

A主线 + 下钻 B模块泳道 C嵌套折叠 D数据流 →我的推荐
A

主线 + 下钻

横向是这一层按顺序发生的事，往下是「钻进某一步里面」。箭头从代码里那一行出发，指向被调用的函数，标签写返回什么。更深的层先折叠成小卡，只显示输入输出。

适合

从入口一路往下读，最接近「读代码时脑子里的样子」。每一层都能单独看懂，复习时从左上角顺着走。

代价

调用链很深时会往下越拖越长，需要靠折叠控制。跨模块的来回调用（比如 vLLM 的 worker 通信）不如泳道清楚。

追踪数据怎么填

箭头标签填真实的返回值形状，循环箭头填实际次数（比如 prefill 1 次、decode 37 次），折叠小卡填记录到的入参和返回值。

B

模块泳道

每个类或模块一条横道，时间从左往右。每一步只是一个小块，点开才看代码。一眼能看出「控制权在谁手里」，以及谁和谁在来回交互。

适合

模块多、来回调用多的系统：调度器和 BlockManager 之间的分配与释放、DeepEP 的多进程通信，每个进程一条道就行。

代价

代码只能点开看，画面上看不到代码本身。和 UML 时序图最像，你说过不想要 UML 的感觉，这是风险。

追踪数据怎么填

追踪记录天然就是「谁在什么时间调用了谁」，可以直接按时间排出来。小块的宽度还可以表示耗时。

C

嵌套折叠

调用关系用「盒子套盒子」表示，像带代码的大纲。每个盒子一行摘要，展开才看代码。点左边的小三角试试。

适合

层级关系最清楚，展开收起最自然，不用手动摆位置。很适合作为侧边栏里的「目录」。

代价

不像白板，更像文档或 IDE 的大纲。没法表达跨层的跳跃、数据从哪里流到哪里，也不能自由摆放笔记和图片。

追踪数据怎么填

每个盒子右侧填调用次数和耗时，结构上就是一张可以读代码的火焰图。

D

数据流

节点是「数据」，箭头是「函数」。看的是一个 prompt 怎么一步步变成 token：字符串、Sequence、张量、logits，再回到 Sequence。函数名可以点开看代码。

适合

理解模型和 kernel 时最有用：形状怎么变、KV cache 写到哪。到了 Triton 和 CUDA，这种视角比调用关系更重要。

代价

控制逻辑（调度策略、抢占、什么时候 prefill）几乎画不出来，只适合看「数据通路」。

追踪数据怎么填

最直接：节点就是追踪记录到的值的摘要。图中 N、B、H、V 现在是符号，追踪后会换成真实数字。

我的推荐

A 当主画布，再借另外两种的一部分，它们不冲突：

  1. A 是默认画法。白板的主体是「主线 + 下钻」，你手工搭的和追踪生成的都长这样。
  2. D 变成箭头上的数据标签。不单独做一种视图，A 的每条箭头都可以显示形状，追踪后自动填上。
  3. C 做成侧边栏大纲。白板上所有卡片按调用层级列成可折叠的树，点一项就跳过去。
  4. B 放到以后。等读 DeepEP、vLLM 多进程时，再加一个「按进程分道」的视图。
